# Tech Writing For Qiita

## Instructions

1. 想定読者は初級〜中級をデフォルトにし、冒頭で到達目標を明記する
2. 構成は「背景→仕組み→実装→デバッグ/ハマりどころ→まとめ」を基本にする
3. サンプルは最小再現と実運用例を分け、なぜその設計にしたかを書く
4. 各見出しに「読者が得る価値」を1行で入れる
5. 公開前に前提条件、実行環境、再現手順、失敗時の確認ポイントを点検する

## Publication Safety

- 公開投稿（`private: false`）は絶対に行わない
- Qiita APIで作成する場合は常に下書き（`private: true`）のみ
- 公開操作はユーザーがQiita画面で最終確認して実施する

## Writing Style

- 文体は「です/ます調」に固定する
- 断定は根拠とセットで書く
- 専門用語は初出時に1行で補足する

## Heading Rules

- 見出しは H2/H3 を基本にし、H4 以降は使わない
- H2 は記事の主要章、H3 は手順・補足・注意点に限定する
- 1つの H2 配下に H3 が多すぎる場合は章を分割する

## Topic Priorities

## Title Patterns

- 【初心者向け】【入門】<技術名>とは？<実務価値>まで解説
- <技術名>で<課題>を解決する実践手順
- 現場で使える<技術名>の<具体テーマ>ガイド

## Review Checklist

- [ ] タイトルに技術要素と価値が入っている
- [ ] 冒頭で対象読者とゴールが明示されている
- [ ] 文章が全体として「です/ます調」で統一されている
- [ ] 見出しが H2/H3 粒度で整理されている
- [ ] 仕組み説明と実装手順のつながりが明確
- [ ] 手順が再現可能である
- [ ] コードと説明の対応が取れている
- [ ] デバッグ観点または失敗時の確認ポイントがある
- [ ] タグが優先順に沿って選定されている
- [ ] まとめに再利用可能な学びがある
