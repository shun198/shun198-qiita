# Claude / Codex / Cursor 向け skills リポジトリを作って運用する手順

## この記事でわかること

- 複数の AI ツールで共通利用できる skills リポジトリの作り方がわかります。
- Cursor / Claude / Codex の3環境で再利用するための配置ルールがわかります。
- セットアップスクリプトでローカル環境に展開する方法がわかります。

## 対象読者

- 複数の AI コーディングツールを使い分けている方
- プロンプトや運用ルールを使い回したい方
- 実装・レビュー・技術記事作成の品質を揃えたい方

## 背景と課題

AI ツールごとに都度プロンプトを作る運用では、品質や観点がぶれやすいです。  
特に実装とレビュー、技術記事作成では、毎回同じ指示を再現したいです。

## 仕組みの要点

リポジトリを共通母体にして、ツール別ディレクトリに skills と prompts を配置します。  
セットアップスクリプトでローカルの各設定ディレクトリへシンボリックリンクします。

## 実装

構成例は次のとおりです。

- `cursor/skills`: Cursor 用 `SKILL.md`
- `cursor/prompts`: Cursor のベースプロンプト
- `claude/skills`, `claude/prompts`
- `codex/skills`, `codex/prompts`
- `scripts/setup-all-skills.sh`: 一括セットアップ

記事作成やレビューなどの用途ごとにスキルを分けると、再利用しやすくなります。

## 動作確認

以下のように実行して、各ディレクトリにリンクが作成されることを確認します。

```bash
./scripts/setup-all-skills.sh
```

## デバッグ / つまずきポイント

- 環境変数ファイルが `.gitignore` されているかを確認します。
- スキル名は小文字ハイフンで統一します。
- 1スキル1目的を徹底し、長くなりすぎる場合は分割します。

## まとめ

skills リポジトリを作ると、AI ツールをまたいでも運用品質を揃えやすくなります。  
最初は実装・レビュー・技術記事作成の3系統から始めると、効果を実感しやすいです。
